Record Row Design Exploration

Records are input-only (no output/assistant message). The row needs to show:
1. The input question   2. Scores from multiple eval/training jobs   3. Which source part the record is linked to

Option A — Dedicated Score Columns per Job

Recommended

Each eval/training job gets its own column. Score header shows job name + type. Trend arrows show improvement between eval runs.

# Input Source

5 Can you give an example of a pawn fork? + generated 0.81 0.83 ↑ pending

Pros: Clear, scannable. Each job's scores are directly comparable vertically. Trend arrows show improvement. Source ref shows the knowledge part lineage.
Cons: Gets wide with many jobs (3-4 max before horizontal scroll). Column headers need abbreviation for long job names.
Source column: Shows the knowledge source part this record was generated from. Empty = no link. "generated" = AI-generated without specific source.

Option C — Hybrid (Latest + History)

Hybrid

Shows the latest eval score prominently, with a compact sparkline of historical scores. Source ref integrated into the row.

Pros: Best of both worlds — prominent latest score + visual trend history. Sparkline is space-efficient.
Cons: More complex to implement. Sparkline can be hard to read at small sizes.
Best for: When you want to emphasize improvement over time while keeping the table compact.

Source Reference Display

How to show the link between a record and its knowledge source part.

Style 1: Tag
📄 ch.1 §3 — Forks
Compact. Shows part reference + title.
Style 2: Inline text
chess-tactics.pdf › ch.1
Simple. Shows filename + part.
Style 3: Generated
+ generated
For AI-generated records without source.
Style 4: No link
—
Record has no source linkage.
